FERMOR THOUGHT — IMPLEMENTATION RULES

1. Name the component FermorThought.

2. FermorThought is a signature Fermor pattern.

3. Do not treat it as a generic Card.

4. Do not treat it as a NotificationCard.

5. The pattern represents:
   Data → Interpretation → Context → Action.

6. Use Sparkles from Lucide as the Fermor AI identifier.

7. Do not use emoji or robot icons.

8. Use Fermor's AI semantic accent color.

9. Each Home page should display a maximum
   of one primary Fermor Thought.

10. Do not create an AI feed on Home.

11. AI Thought content must be based on
    actual user financial data.

12. Never fabricate financial information.

13. Never present unsupported AI assumptions
    as financial facts.

14. Separate factual observations from
    AI interpretation.

15. Use factual language whenever possible.

16. Avoid aggressive financial recommendations.

17. Do not tell users what financial product
    they must buy or sell.

18. Prefer decision-support language:
    "Explore"
    "Understand"
    "Consider"
    "See what changed"

19. The primary action should take the user
    to the relevant financial context.

20. Ask Fermor should open with the relevant
    context already attached.

21. Do not require the user to repeat
    the question that generated the insight.

22. Primary CTA and Ask Fermor should have
    different visual hierarchy.

23. Support:
    loading
    thinking
    success
    empty
    error.

24. Do not generate a fake thought when
    meaningful data is unavailable.

25. If there is no meaningful insight,
    the Home component may be omitted.

26. Use subtle Motion.dev transitions only.

27. No continuous animations.

28. No glowing AI borders.

29. No excessive gradients.

30. No glassmorphism unless explicitly
    established as part of the Fermor system.

31. Use existing Fermor typography tokens.

32. Use existing Fermor spacing tokens.

33. Use existing Fermor button components.

34. Do not create custom button styles
    inside FermorThought.

35. Use Lucide Icons exclusively.

36. The component must be responsive.

37. Desktop should use a wide horizontal
    composition.

38. Mobile should stack content and actions.

39. Maintain a calm, intelligent,
    trustworthy financial tone.

40. Fermor should feel like a financial
    intelligence assistant, not a generic
    AI chatbot.


DESIGN NOTES

• Fermor Thought is a signature product pattern.

• It is different from Financial Insight Feed.

• Financial Insight = observation.

• Fermor Thought = observation + interpretation
  + context + next action.

• Home should show only one primary thought.

• The component should never feel like
  a generic AI chatbot.

• Use Sparkles as Fermor's AI identifier.

• Avoid robot icons and AI clichés.

• Keep the visual treatment subtle.

• Use Fermor's existing blue visual language.

• Don't use excessive AI gradients or glow.

• The primary action should lead to the
  relevant financial analysis.

• Ask Fermor should preserve context.

• AI responses must be explainable.

• AI should never fabricate financial facts.

• Avoid authoritative investment instructions.

• Use AI to help users understand and explore,
  not blindly follow recommendations.

• If no meaningful insight exists,
  don't invent one.

• Home = one meaningful thought.
  Insights = detailed observations.
  Ask Fermor = conversation.
